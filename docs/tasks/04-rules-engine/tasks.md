- [x] **TASK-014p:** Taint through function parameters — `visitParameter` resolves a parameter from the call sites of its function, matching a destructured name to the argument property or JSX attribute of the same name and reading the exact key off a spread whose object literal is visible. Bounded by `MAX_PARAM_HOPS = 1` and to call sites in the same file, indexed once per file and cached on the resolver. This is what makes a leak inside a local helper component report at the helper's own JSX, with the caller's value in the trace.

Known limits (documented, not bugs): a parameter whose callers live in another module isn't followed, because finding every caller across a project needs a reference search too expensive to run at each sink; two import hops aren't followed; `fetch` wrapped in a class method resolves only if the method is reachable by symbol. Scan cost on a 979-file app: about 14 s and ~1 GB RSS, unchanged by the parameter walk — caching is still open.
