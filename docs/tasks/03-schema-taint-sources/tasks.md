# Epic 03 Tasks — in order

- [x] **TASK-009:** Create schema provider interface `src/schema/types.ts` (`TaintSource`, `SchemaProvider`). Landed early, as part of Epic 01/TASK-020, since `init` needed the contract before this epic started.
- [x] **TASK-010:** `prisma.ts` `extract()` — parses `.prisma` text (`parsePrismaSchema`): one source per column of every `model`, keeps FK scalars, skips relation fields (typed as another model or carrying `@relation`) and `@@` lines; tolerates one-line models. Origin `prisma:<Model>.<field>`.
- [x] **TASK-011:** `src/classification/classify.ts` — `isSensitiveName` / `classifySources`. Normalized substring match for keywords ≥ 4 chars (`token` catches `accessToken`), **whole-word only for ≤ 3 chars** (so `ssn` can't fire inside `previou-ssn-apshot` — a real hit on ipractis). `exclude` matches exact field name or exact origin. Defaults trimmed after the ipractis run: `session` and `stripe` removed (they flagged lesson-session and fee-config columns), `otp` added; projects add domain keywords themselves. Snapshot keeps **all** fields; classification runs at scan time, so keyword edits take effect without `sync`.
- [x] **TASK-011a:** `openapi.ts` `extract()` — file or URL (`headers` config for `apikey` etc.), JSON or YAML; walks both OpenAPI 3 `components.schemas` and Swagger 2 `definitions` (what PostgREST serves), recursing into nested objects, `allOf` and array `items`. Origin `openapi:<Schema>.<prop>`.
- [x] **TASK-011b:** `zod.ts` `extract()` — syntax-only ts-morph project over the configured glob; every `z.object` / `z.strictObject` / `z.looseObject` literal's keys, nested included, attributed to the enclosing `const`. Origin `zod:<file>:<Name>.<key>`. `detect()` stays `false` by design.
- [ ] **TASK-011c:** Server-ingress tracking (`fetch`/`axios` results tainted-by-default until projected). This is binding-provenance work — it belongs in `ast/render-graph.ts` (P1) next to the rules that consume it, so it moves to Epic 04. Left here as a pointer.
- [x] **TASK-011d:** `supabase.ts` `extract()` — reads the generated `Database` type through the **type checker** (not text), every `Row` of `Tables` and `Views`, skipping `Insert`/`Update`/`Enums`/`__InternalSupabase`. Verified on ipractis: 558 fields / 45 tables+views in ~350 ms. New `drizzle.ts` provider: `pgTable`/`mysqlTable`/`sqliteTable`, object or callback form, prefers the DB column name from the builder chain (`text("password_hash").notNull()`) over the property key. Origins `supabase:<schema>.<table>.<column>`, `drizzle:<table>.<column>`.

- [x] **TASK-011f:** Explicit sensitivity overrides — `sensitiveFields.include` (pin an exact field/origin the keywords missed: other languages, domain terms) and `sensitiveFields.exclude` (never sensitive, wins over everything) in the config; `keywords.exclude` kept as a legacy alias. `init` **seeds `sensitiveFields.include`** with the keyword hits so the config file shows the flagged list and the user edits it directly; `sync` never rewrites the config; keywords keep applying on top at scan time. `sync`/`init` print the full list with the edit hint. Snapshot stays facts-only.

- [ ] **TASK-011e:** Supabase without a generated types file — fetch the schema from the project itself. Detect `NEXT_PUBLIC_SUPABASE_URL` + `NEXT_PUBLIC_SUPABASE_ANON_KEY`/`SUPABASE_SERVICE_ROLE_KEY` in `.env*`, and offer (opt-in, never default) to GET `<url>/rest/v1/` with the key as `apikey` — PostgREST serves an OpenAPI document listing every exposed table and column, which normalizes through the same path as TASK-011a.
