# Antra Web (Landing + Docs) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `apps/web` — a Next.js 16 / React 19 / Tailwind v4 app — to the pnpm workspace, with a landing page and a `/docs` site, visually matching the "Modernist" design import but with all product-claim copy grounded in the real CLI, rule set, and config schema.

**Architecture:** New pnpm workspace member at `apps/web`, scaffolded with `create-next-app` then customized. Landing page is a composition of per-section modules under `modules/landing/sections/*`. Docs are plain `.mdx` files under `content/docs/**`, rendered through a single optional-catch-all route (`app/docs/[[...slug]]/page.tsx`) using `next-mdx-remote/rsc`; the sidebar/TOC/prev-next nav is derived from the content folder at build time via `modules/docs/get-nav.ts` (frontmatter-driven, no hand-maintained nav array).

**Tech Stack:** Next.js ^16.2.9 (App Router), React ^19.2.8, Tailwind CSS ^4.3.3 (`@tailwindcss/postcss`), `next-mdx-remote` (rsc entrypoint), `gray-matter`, `zod`, TypeScript ^5.9.3, Vitest (for the one piece of real logic: nav-tree building).

**Spec:** `docs/superpowers/specs/2026-09-08-antra-web-design.md`

## Global Constraints

- Root CLI package (`src/`, `bin/`, published as `boundary-guard`) and `studio/` are **not modified** by this plan.
- No `packages/` workspace member is created — `apps/web` is the only new member.
- No Turborepo — plain pnpm workspaces (`pnpm --filter web <script>`).
- Docs command examples show the bin as `antra` (forward-looking; the actual package rename is out of scope). Anything that is a **literal string the real code parses or writes** — the config filename `boundary-guard.config.json` and the suppression directive `boundary-guard-disable-next-line` — is shown exactly as the source defines it today, not renamed, because renaming those in docs would describe behavior that doesn't exist.
- Severities are `error` | `warning` only — never invent `critical`/`high`/`medium`/`low`.
- No live/interactive demo section on the landing page (the design mockup's `#scan` typed-animation section is not built).
- No hardcoded brand/tagline/GitHub-URL strings in components — all read from `apps/web/config/site.ts`.
- Every doc code example uses real command names and real flags from `src/cli/index.ts` (cited per-task below) — no invented flags.

- [ ] **Step 3: No-flash theme script**

Create `apps/web/components/shared/theme-script.tsx`:

```tsx
const THEME_SCRIPT = `
(function () {
  try {
    var stored = localStorage.getItem("antra-theme");
    var dark = stored ? stored === "dark" : window.matchMedia("(prefers-color-scheme: dark)").matches;
    if (dark) document.documentElement.classList.add("dark");
  } catch (e) {}
})();
`;

export function ThemeScript() {
  // eslint-disable-next-line react/no-danger -- inline script must run before paint
  return <script dangerouslySetInnerHTML={{ __html: THEME_SCRIPT }} />;
}
```

- [ ] **Step 4: Theme toggle client component**

Create `apps/web/components/shared/theme-toggle.tsx`:

```tsx
"use client";

import { useEffect, useState } from "react";

export function ThemeToggle() {
  const [dark, setDark] = useState(false);

  useEffect(() => {
    setDark(document.documentElement.classList.contains("dark"));
  }, []);

  function toggle() {
    const next = !dark;
    setDark(next);
    document.documentElement.classList.toggle("dark", next);
    try {
      localStorage.setItem("antra-theme", next ? "dark" : "light");
    } catch {
      // localStorage unavailable (private mode) — theme just won't persist
    }
  }

  return (
    <button
      type="button"
      onClick={toggle}
      className="border border-[var(--color-divider)] px-3 py-1.5 text-xs font-heading font-semibold uppercase tracking-wide hover:bg-[var(--color-surface)]"
      title="Toggle light and dark theme"
    >
      {dark ? "Light" : "Dark"}
    </button>
  );
}
```

```tsx
import type { ReactNode } from "react";

type ButtonProps = {
  href: string;
  children: ReactNode;
  variant?: "primary" | "secondary";
  external?: boolean;
};

const BASE =
  "inline-flex items-center justify-center gap-2 whitespace-nowrap px-5 py-3 text-sm font-heading font-semibold";

export function Button({
  href,
  children,
  variant = "secondary",
  external = false,
}: ButtonProps) {
  const className =
    variant === "primary"
      ? `${BASE} bg-accent-500 text-white hover:bg-accent-600`

    return (
      <a href={href} target="_blank" rel="noreferrer" className={className}>
        {children}
      </a>
    );
  }
  return (
    <Link href={href} className={className}>
      {children}
    </Link>
  );
}
```

```tsx
"use client";

import { useState } from "react";

export function CodeBlock({
  lang,
  children,
}: {
  lang: string;
  children: string;
}) {
  const [copied, setCopied] = useState(false);

  async function copy() {
    try {
      await navigator.clipboard.writeText(children);
      setCopied(true);
      setTimeout(() => setCopied(false), 1600);
    } catch {
      // clipboard API unavailable — nothing to fall back to
    }
  }

  return (
    <div className="border border-[var(--term-line,#3a3736)] bg-[#1a1918] text-[#f1efee]">
      <div className="flex items-center gap-3 border-b border-[#3a3736] px-4 py-2 text-[11px] font-mono uppercase tracking-wide text-[#9a9694]">
        <span>{lang}</span>
        <button
          type="button"
          onClick={copy}
          className="ml-auto border border-white/30 px-2 py-0.5 text-[11px] font-mono uppercase tracking-wide hover:border-accent-400 hover:text-accent-400"
        >
          {copied ? "Copied" : "Copy"}
        </button>
      </div>
      <pre className="overflow-auto p-4 text-[13px] leading-relaxed">
        <code>{children}</code>
      </pre>
    </div>
  );
}
```

```tsx
"use client";

import { useState } from "react";

type TabItem = { label: string; code: string };

export function Tabs({
  items,
  lang = "bash",
}: {
  items: TabItem[];
  lang?: string;
}) {
  const [active, setActive] = useState(0);

  return (
    <div>
      <div className="flex flex-wrap border-b-2 border-[var(--color-divider)]">
        {items.map((item, i) => (
          <button
            key={item.label}
            type="button"
            onClick={() => setActive(i)}
            className={`-mb-0.5 border-b-2 px-4 py-2 font-mono text-xs ${
              i === active
                ? "border-accent-500 text-[var(--color-ink)]"
                : "border-transparent text-[var(--color-ink)]/60 hover:text-accent-500"
            }`}
          >
            {item.label}
          </button>
        ))}
      </div>
      <CodeBlockBody lang={lang} code={items[active]?.code ?? ""} />
    </div>
  );
}

function CodeBlockBody({ lang, code }: { lang: string; code: string }) {
  return (
    <div className="border border-t-0 border-[#3a3736] bg-[#1a1918] text-[#f1efee]">
      <pre className="overflow-auto p-4 text-[13px] leading-relaxed">
        <code>{code}</code>
      </pre>
      <div className="sr-only">{lang}</div>
    </div>
  );
}
```

```ts
import { existsSync, readdirSync, readFileSync } from "node:fs";
import { join } from "node:path";

import matter from "gray-matter";
import { z } from "zod";

const frontmatterSchema = z.object({
  title: z.string(),
  description: z.string(),
  order: z.number(),
});

export type DocFrontmatter = z.infer<typeof frontmatterSchema>;

export type DocsNavItem = { slug: string; title: string; order: number };
export type DocsNavGroup = {
  slug: string;
  label: string;
  items: DocsNavItem[];
};

/** Fixed display order and label for each top-level content/docs folder. */
export const GROUP_ORDER: { slug: string; label: string }[] = [
  { slug: "getting-started", label: "Getting Started" },
  { slug: "concepts", label: "Core Concepts" },
  { slug: "commands", label: "Commands" },
  { slug: "studio", label: "Antra Studio" },
  { slug: "configuration", label: "Configuration" },
  { slug: "rules", label: "Rules" },
  { slug: "ci", label: "CI/CD" },
];

const DEFAULT_DOCS_DIR = join(process.cwd(), "content", "docs");

function readFrontmatter(filePath: string): DocFrontmatter {
  const raw = readFileSync(filePath, "utf-8");
  const { data } = matter(raw);
  return frontmatterSchema.parse(data);
}

function readGroupItems(baseDir: string, groupSlug: string): DocsNavItem[] {
  const groupDir = join(baseDir, groupSlug);
  if (!existsSync(groupDir)) return [];
  return readdirSync(groupDir)
    .filter((name) => name.endsWith(".mdx"))
    .map((name) => {
      const fileSlug = name.replace(/\.mdx$/, "");
      const fm = readFrontmatter(join(groupDir, name));
      return {
        slug: `${groupSlug}/${fileSlug}`,
        title: fm.title,
        order: fm.order,
      };
    })
    .sort((a, b) => a.order - b.order);
}

export function getDocsNav(baseDir: string = DEFAULT_DOCS_DIR): DocsNavGroup[] {
  return GROUP_ORDER.map((group) => ({
    slug: group.slug,
    label: group.label,
    items: readGroupItems(baseDir, group.slug),
  })).filter((group) => group.items.length > 0);
}

export function getFlatDocsList(
  baseDir: string = DEFAULT_DOCS_DIR,
): DocsNavItem[] {
  return getDocsNav(baseDir).flatMap((group) => group.items);
}

export function getDocSource(
  slug: string[],
  baseDir: string = DEFAULT_DOCS_DIR,
): { frontmatter: DocFrontmatter; content: string } | null {
  const filePath = join(baseDir, ...slug) + ".mdx";
  if (!existsSync(filePath)) return null;
  const raw = readFileSync(filePath, "utf-8");
  const { data, content } = matter(raw);
  return { frontmatter: frontmatterSchema.parse(data), content };
}
```

```tsx
/** Extracts language + raw text from a fenced-code `<pre><code className="language-x">` pair so `pre` can hand off to CodeBlock. */
function extractCode(children: ReactNode): { lang: string; code: string } {
  const child = children as {
```

```mdx
title: Trust Boundaries
description: A boundary is any point where a value moves between React Flight, a Server Action, a route handler, or markup.
order: 1
---

React Server Components let server-only code sit next to client code in the same file tree. That convenience is also the risk: a value that's safe on the server — a full user record, a `process.env` secret — can end up serialized into the client bundle if it's passed across the wrong boundary.

## Boundaries Antra classifies

- **Server → Client.** A Server Component passing props, spread attributes, or children into a Client Component.
- **Client → Server Action.** A Server Action's parameters, arriving from the client as untrusted input.
- **Request → route handler.** A route handler reading a request body with `.json()`, `.formData()`, `.text()`, or `req.body`.
- **Value → markup.** A value rendered directly into JSX output rather than passed through a component prop.

## Not every crossing is a bug

Antra reports a crossing when the receiving side has no validation, no projection to the needed fields, and no sanitizer in the value's path — see [Findings & Severity](/docs/concepts/findings-and-severity) and [Suppressions & Baselines](/docs/concepts/suppressions-and-baselines).
```

## Two severities

Antra has exactly two severity levels — there is no "info" or "critical" tier:

- **error** — the crossing is treated as a defect. `--fail-on-violation` exits non-zero when any error-severity finding is unsuppressed.
- **warning** — worth reviewing, but does not fail the build on its own. `-s`/`--strict` promotes warnings to errors.

## The four rules

| Rule     | Severity | Fires when                                                                 |
| -------- | -------- | -------------------------------------------------------------------------- |
| `BG-001` | error    | A sensitive value is passed to a Client Component from the server.         |
| `BG-002` | error    | A Server Action or route handler accepts input without validation.         |
| `BG-003` | warning  | A full fetch/DB result is passed whole to a Client Component, unprojected. |
| `BG-004` | error    | A sensitive value is rendered directly into markup.                        |

Full detail on each rule, with real examples, is in the [Rules reference](/docs/rules/bg-001).

````
- [ ] **Step 2: BG-001**

Create `apps/web/content/docs/rules/bg-001.mdx`:

```mdx
---
title: BG-001 — server-to-client leak
description: A concrete sensitive value is handed to a Client Component as a prop, spread, or child from a Server Component.
order: 1
---

**Severity:** error

Fires when a schema field, a keyword-matched field, or a `process.env` value is passed to a Client Component and therefore serialized across the React Flight boundary into something the browser can read.

```tsx
// app/dashboard/page.tsx  (Server Component)
export default function DashboardPage() {
  return <ApiKeyDisplay secret={process.env.API_SECRET} />;
}
````

## Fixing it

Don't pass the raw value — pass a redacted or derived version, or move the value out of the client render path entirely:

```tsx
export default function DashboardPage() {
  return <ApiKeyDisplay secret={redact(process.env.API_SECRET)} />;
}
```

If the value is safe once redacted, configure `redact` as a [sanitizer](/docs/configuration/config-reference) so the finding clears on its own.

````

- [ ] **Step 3: BG-002**

Create `apps/web/content/docs/rules/bg-002.mdx`:

```mdx
---
title: BG-002 — unvalidated input
description: A Server Action or route handler accepts input without validation.
order: 2
---

**Severity:** error

Fires on a Server Action with parameters, or a route handler that reads the request body (`.json()`, `.formData()`, `.text()`, or `req.body`), where no call to a configured validator appears anywhere in the function body. Client input is untrusted by definition — GET/HEAD/OPTIONS handlers are exempt, since they carry no body to validate.

```ts
"use server";

export async function updateProfile(name: string, bio: string) {
  await db.user.update({ data: { name, bio } });
}
````

## Fixing it

Validate before the value reaches anything that persists or forwards it:

```ts
"use server";

const schema = z.object({ name: z.string().max(80), bio: z.string().max(500) });

export async function updateProfile(name: string, bio: string) {
  const input = schema.parse({ name, bio });
  await db.user.update({ data: input });
}
```

````

- [ ] **Step 4: BG-003**

Create `apps/web/content/docs/rules/bg-003.mdx`:

```mdx
---
title: BG-003 — unprojected result
description: An unprojected fetch or database result is passed whole to a Client Component.
order: 3
---

**Severity:** warning

Fires when a full record — everything a query returned, not just the fields the client actually needs — is handed to a Client Component. Even if none of the fields are individually flagged as sensitive today, passing the whole object means a later schema change (a new column) silently starts reaching the client with no new finding to catch it.

```tsx
export default async function ProfilePage() {
  const user = await db.user.findUnique({ where: { id } });
  return <ProfileCard user={user} />; // whole row, not a projection
}
````

## Fixing it

Project to exactly the fields the client renders:

```tsx
export default async function ProfilePage() {
  const user = await db.user.findUnique({
    where: { id },
    select: { name: true, avatarUrl: true },
  });
  return <ProfileCard user={user} />;
}
```
